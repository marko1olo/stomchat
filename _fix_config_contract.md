## Замер 1. Что именно читает код (AST по 113 файлам, не regex)

Инструмент замера — разбор через `ast` всех `*.py` в корне (113 файлов,
подкаталогов с кодом нет, проверено `fd -I -e py`). Regex по `config\.ИМЯ`
даёт мусор: `config.py` в комментарии совпадает как имя `py`,
`config.example.py` — как `example`, `config.json_loads` в docstring
`test_report_targets.py` — как `json_loads`. Ни одно из них не атрибут.
Поэтому и в замере, и в тесте используется AST: `ast.Attribute` над
`ast.Name` с учётом `ctx` (чтение против присваивания) плюс разбор
`getattr`/`hasattr` по числу аргументов.

**16 имён читаются как обязательные:**

```
API_HASH  API_ID  BOT_TOKEN  DB_PATH  GEMINI_MODEL  GOOGLE_KEYS  GROQ_KEYS
GROQ_MODEL  REPORT_CHAT_ID  REPORT_HOUR  REPORT_TARGETS  SEARCH_PROVIDER
SESSION_NAME  SOURCE_CHAT_ID  TAVILY_API_KEY  TELEGRAPH_TOKEN
```

Самые горячие: `SOURCE_CHAT_ID` — 29 обращений (27 в боевом коде),
`DB_PATH` — 17, `GOOGLE_KEYS` — 11.

**2 имени читаются только с запасным значением (необязательные):**

| Имя | Где | Как |
|---|---|---|
| `DENTAL_KEYWORDS` | `dental_vocab.py:92` | `getattr(config, "DENTAL_KEYWORDS", None)` — необязательное расширение словаря |
| `OPENROUTER_KEYS` | `gemini_client.py:293-294` | имя лежит в кортеже цикла, читается `getattr(config, attr, None)`; в живом `config.py` его нет вообще |

**Правило «обязательное против необязательного»** (оно же зашито в тест):

* `config.ИМЯ` в контексте чтения — **обязательное**. Нет имени → `AttributeError`.
* `getattr(config, "ИМЯ")` в два аргумента — **обязательное**: `getattr` без
  третьего аргумента бросает то же `AttributeError`.
* `getattr(config, "ИМЯ", запас)` в три аргумента — **необязательное**: у кода
  есть свой запас, отсутствие имени законно.
* `hasattr(config, "ИМЯ")` — **необязательное**: это прямая проверка на наличие.
* `config.ИМЯ = ...` (контекст `Store`) — **не чтение**: так тесты подменяют
  конфиг. В обязательные не идёт (таких имён, встречающихся только на
  присваивании, в дереве нет — все они и читаются тоже).

## Замер 2. Дыра в шаблоне до правки

Загрузка `config.example.py` через `importlib` проходит **без ошибки** — то есть
установка «по шаблону» не сообщает о проблеме ни звуком. Из 16 обязательных имён
в шаблоне не объявлено **3**: `API_ID`, `SOURCE_CHAT_ID`, `REPORT_TARGETS`.

Когда каждое из них укусит (замер по AST: уровень модуля против тела функции):

| Имя | Первое обращение | Когда падает | Что видит врач |
|---|---|---|---|
| `API_ID` | `main.py:888` — `TelegramClient(...)` на уровне модуля | при импорте `main.py` | бот не стартует, `AttributeError` в консоли — громко |
| `SOURCE_CHAT_ID` | `main.py:1776` — `WATCHED_CHATS = [...]` на уровне модуля | при импорте `main.py` | бот не стартует — громко |
| `REPORT_TARGETS` | `main.py:591` внутри `resolve_report_targets()` | в рантайме, **проглатывается** `except Exception` | бот работает, но ни дайджеста, ни недельной сводки не получает НИКТО из 749 врачей; в журнале одна строка ERROR |

Уточнение к формулировке задачи: «падает в рантайме, а не на старте» верно ровно
для `REPORT_TARGETS`. Два остальных имени валят **импорт** `main.py`, потому что
`TelegramClient` и `WATCHED_CHATS` собираются на уровне модуля. Хуже как раз
третий случай — молчаливый: `resolve_report_targets()` ловит любое исключение,
пишет ERROR и возвращает пустой список, так что бот выглядит живым.

## Замер 3. Имена, объявленные в шаблоне и не читаемые никем

`GROQ_VISION_MODEL`, `SUMMARY_INTERVAL`, `MAX_MSGS` объявлены и в живом
`config.py`, и в шаблоне, но `rg` по всему дереву не находит ни одного
обращения `config.ИМЯ` к ним — только сами строки объявления. Это мёртвый груз,
но он есть в ЖИВОМ конфиге, а задача — соответствие форме живого конфига,
поэтому из шаблона они не удаляются. Отмечено как долг, решение за лидом.

## Замер 4. Утечка в самом шаблоне (до правки)

В версионном `config.example.py` строкой 3 стоит `SESSION_NAME = "bot_session"` —
это имя файла сессии Telethon, и рядом в корне лежит `bot_session.session`
(139 264 байта), то есть имя не выдумано, а взято с рабочей машины.
`*.session` в `.gitignore`, а имя сессии — нет. Правкой убрано:
в шаблоне остаются только имена переменных окружения и пустые значения.

## Правка

`config.example.py` переписан по форме живого `config.py`: те же импорты,
`load_dotenv()`, функция `get_env(key, default, required)`, функция
`parse_keys()`, те же три блока валидации (int-приведение `API_ID`,
int-или-None для `SOURCE_CHAT_ID`, `json.loads` для `REPORT_TARGETS`), те же
два предупреждения (нет ни одного ключа нейросети; выбран Tavily без ключа).

Из живого `config.py` **не скопировано ни одно значение**: ни токена, ни ключа,
ни id чата, ни числа, ни имени сессии, ни имени модели. В шаблоне только имена
переменных окружения (`TG_API_ID`, `SOURCE_CHAT_ID`, `REPORT_TARGETS`, ...),
пустые значения нужного типа и русские комментарии с последствием для врача.
Значения, которые в версионном шаблоне были и раньше (`DB_PATH`,
`SUMMARY_INTERVAL`, `MAX_MSGS`, `REPORT_HOUR = 0`) сохранены как были —
`REPORT_HOUR = 0` намеренно, на него ссылаются комментарии `main.py:488` и
`test_fix_scheduler.py:12,194`.

Шаблон cp1251-безопасен: ни одного символа вне cp1251 (это уже сторожит
`test_report_targets.py`, проверка `[9]`, и она остаётся зелёной).

## Тест

`test_config_contract.py` — поведенческий, не текстовый:

1. Собирает контракт AST-разбором всех `*.py` (правило обязательности выше).
2. **Загружает** шаблон как модуль через `importlib` с поддельным окружением и
   проверяет `hasattr` каждого обязательного имени на настоящем объекте модуля.
   Это не «в исходнике есть такая строка», а «модуль после исполнения отдаёт
   атрибут» — то есть ровно то, что делает `import config` у врача.
3. Проверяет ТИПЫ и валидации поведением: пустой `REPORT_TARGETS` даёт список,
   битый JSON даёт список и не роняет импорт, нечисловой `TG_API_ID` даёт
   `SystemExit`, пустой `SOURCE_CHAT_ID` даёт `None`, `parse_keys` разбирает
   запятые.
4. Проверяет, что в шаблоне НЕТ значений: ни одной строки длиной >= 20 из
   алфавита ключей, ни отрицательного id чата, ни `.session`.
5. Мета-проверка с зубами: делает во временном каталоге копию шаблона с
   вырезанным обязательным именем и убеждается, что проверка (1)+(2) на ней
   ПАДАЕТ. Без этой проверки пункт (2) мог бы ничего не значить.

## Замер 5. Перепроверка полноты сборщика (независимая, `_probe_cfgnames.py`)

Сборщик видит только `config.ИМЯ`, `getattr`/`hasattr`. Проверил, чем можно
прочитать конфиг ПОМИМО этого — то есть где контракт мог бы молча недосчитать:

| Способ обойти сборщик | Найдено в дереве |
|---|---|
| `from config import ИМЯ` (это `ImportFrom`, не `Attribute`) | **0** |
| `importlib.import_module("config")` / `__import__("config")` | 1, и это `_probe_silent.py:79` — черновик другого агента, не боевой код |
| `vars(config)` / `config.__dict__` / `dir(config)` | **0** (три совпадения — в моём же пробнике) |
| `.py` в подкаталогах (сборщик берёт `os.listdir`, не `os.walk`) | **0** |
| файлы, которые сборщик молча пропускает по `except SyntaxError` | **0 из 131** |

То есть на сегодняшнем дереве `Attribute`-разбора достаточно, и тихого недобора
нет. Файлов в корне уже 131 против 113 в замере 1 — параллельные агенты плодят
черновики, набор обязательных имён при этом не изменился (16).

**Слабое место, называю честно:** ноль в первой и последней строке таблицы — это
свойство сегодняшнего дерева, а не гарантия. Появится `from config import X` —
сборщик его не увидит, и тест промолчит. Появится файл с синтаксической ошибкой —
он выпадет из контракта без единого слова. Второе лечится дешево: заменить
`except SyntaxError: continue` на падающую проверку. Не делаю: это заденет
контракт с чужими файлами в момент, когда семь агентов пишут в дерево, и
непарсящийся черновик уронил бы мой тест по чужой причине.

## Замер 6. Провенанс: не собран ли контракт из мусорных черновиков

Тест берёт `os.listdir`, поэтому черновик `_probe_*.py` чужого агента может
добавить имя в контракт и уронить проверку по чужой причине. Проверил каждое из
16 имён на наличие хотя бы одного обращения в БОЕВОМ файле:

**У всех 16 есть боевое обращение — ни одно имя не пришло только из черновиков.**
Перекос заметен, но не опасен: `DB_PATH` — 17 обращений, из них боевых 4;
`GEMINI_MODEL` — 4 обращения, боевое 1; `REPORT_HOUR` — 5, боевых 2. Самые
горячие боевые: `SOURCE_CHAT_ID` 27, `GOOGLE_KEYS` 12, `API_HASH` 7, `API_ID` 7.

**Риск на будущее:** черновик, читающий `config.НОВОЕ_ИМЯ`, добавит его в
`REQUIRED`, и проверка «покрыто каждое обязательное имя» станет красной, хотя
шаблон ни при чём. Сейчас это не так, проверено. Разделение боевых и черновых
файлов в сам тест не зашивал: список префиксов черновиков — соглашение сегодняшнего
дня, а не правило репозитория, и зашивать его значит однажды тихо выкинуть из
контракта настоящий боевой файл.
