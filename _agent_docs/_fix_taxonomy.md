## 4. Саботаж: 8 диверсий, 7 поймано, 1 оказалась пустышкой

Каждая диверсия оставляла файл валидным питоном (это проверялось `compile()` перед
прогоном) — то есть тест ловил СМЫСЛ, а не синтаксис. Откат стоял в `finally` и
сверялся побайтно, поэтому окно со сломанным продакшном длилось секунды.

| # | что сломано | упало проверок | поймано |
|---|---|---|---|
| S1 | `display_name` выдаёт имя РАЗДЕЛА вместо честного «БЕЗ ИМЕНИ» (выдуманное клиническое название) | 1, после усиления теста **2** | да |
| S2 | `token_patterns` снова отбирает подстрокой | 12 (мой 7 + test_savdel_taxonomy 5) | да |
| S3 | `savdel.CAT_MAP = dict(...)` — КОПИЯ вместо того же объекта | 3 (мой 2 + pipeline 1) | да |
| S4 | из `EXPORT_SLUGS` удалены рубрики 8.1.1/9.1.1/10.1.1 | 11 (мой 4 + savdel 6 + pipeline 1) | да |
| S5 | `parse_codes` больше не режет список по запятой | 12 (мой 12, test_savdel_taxonomy **0**) | да |
| S6 | `checker` снова открывает боевую вику НА ЗАПИСЬ | 2 | да |
| S7 | `LEAF_CODES = frozenset(taxonomy.LEAF_CODES)` | 0 | **НЕТ** |
| S7b | `LEAF_CODES = frozenset(sorted(taxonomy.LEAF_CODES))` | 2 (мой 1 + pipeline 1) | да |
| S8 | из текста дерева выпал лист `2.2.6` (2 466 пометок) | 9 (мой 5 + pipeline 4) | да |

Честно про S7: диверсия НЕ была поймана, потому что она ничего не сломала —
`frozenset(f)` в CPython возвращает ТОТ ЖЕ объект (проверено:
`frozenset(f) is f -> True`, `frozenset(sorted(f)) is f -> False`). То есть
пустышкой оказалась диверсия, а не проверка; переделанная S7b поймана двумя
проверками. Пишу как есть, потому что «caught false» из-за неудачной диверсии и
«caught false» из-за дырявого теста — разные вещи, и путать их нельзя.

Честно про S5: `test_savdel_taxonomy.py` поломку разбора списка НЕ ЗАМЕТИЛ вообще
(31/0). Его стенд устроен так, что мультитеговый факт попадает в свою рубрику по
SQL, а учёт неизвестных кодов идёт только по свалке. Значит на разборе списка
кодов держится только мой тест.

Честно про S1: до усиления теста выдуманное имя ловила ОДНА проверка. Добавил две:
«безымянному коду не приписано настоящее клиническое имя» (она перечисляет
приписанные коды) и «безымянный код не выдаётся за имя самим собой». После этого
S1 ловится двумя.

подтем брать из `taxonomy.DISPLAY_NAMES`, а не переписывать. Плюс добавить
проверку «каждый код из WIKI_TREE есть в taxonomy.LEAF_CODES или явно назван
исключением» — иначе кнопка молча пустая.

Отдельно и важнее: `_wiki_code_filter` (строка ~4485) отбирает
`category_code LIKE '%{code}%'` — **подстрокой, без границы токена**. Сейчас это не
даёт врать только потому, что в живой базе нет токенов глубже L3 (замер: уровни
2 и 3, 23 и 87 кодов). До реклассификации такие токены были (`1.3.10`, `2.2.3.1`,
`11.1.1`), и первый же новый факт с кодом `1.3.10` попадёт в кнопку «Профгигиена».
Замер на живой вике для L2-кода: `1.1` по границе токена — 1 118 фактов,
подстрокой — 5 428, то есть **4 310 чужих**. Готовая замена:
`taxonomy.token_sql("category_code")` + `taxonomy.token_patterns(code)`.

### 7.4 `test_import_safety.py` — дырка в сторожевом детекторе

`bare_repo_target` (строка 227) считает целью записи ТОЛЬКО строковый литерал без
разделителя каталогов. Замерено на образцах (`_measure_tax_detector2.py`):

ПОЙМАН   литерал в корне: open("distiller.py", "w")
ПРОПУЩЕН путь через переменную-литерал: P = "distiller.py"; open(P, "w")
ПРОПУЩЕН путь склеен Path-делением: open(ROOT / "distiller.py", "w")
ПРОПУЩЕН io.open(ROOT / "distiller.py", "w")

Второй случай — ровно тот класс, который комментарий этой секции объявляет

что уже есть в файле: прогонять цель через `module_constants`/`target_text` и
считать корнем репозитория также `ROOT / "имя.py"`. Файл не мой и его сейчас
правит другой агент — трогать не стал.
